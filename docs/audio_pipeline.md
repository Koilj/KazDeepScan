# Контракт аудио-конвейера

## Границы входа

MVP принимает только WAV, FLAC, MP3, OGG и M4A. Заявленный HTTP MIME-тип проверяется, но
доверенным не считается: файл обязан успешно пройти `ffprobe`, содержать аудиопоток и иметь
поддерживаемый фактический контейнер. Ограничения по умолчанию: 50 MiB и 10 минут.

`FFmpegClient` никогда не запускает shell; путь к файлу передаётся отдельным аргументом
`subprocess`. Пути к двоичным файлам берутся из `KDS_FFMPEG_BINARY` и
`KDS_FFPROBE_BINARY` либо из `PATH`. Нормализация использует первый аудиопоток и выдаёт
mono PCM S16LE WAV с частотой 16 кГц. Входное имя не используется как имя выходного файла.

## Контроль качества

После нормализации вычисляются peak, RMS dBFS, доля клиппированных сэмплов и DC offset.
Стартовые значения `min_rms_dbfs=-55`, `max_clipped_fraction=0.02` являются
консервативными эксплуатационными ограничениями, а не порогами модели. Они должны быть
перепроверены на product validation set до релиза.

Рабочий VAD — WebRTC VAD с 30-мс фреймами. Если пакет не установлен, конвейер намеренно не
подменяет его энергетическим VAD: это исключает незаметное расхождение development и
production. Простая энергетическая реализация доступна только для изолированных тестов.

## Окна для модели

Инференс использует окна 64 600 сэмплов (4.04 с) с шагом 32 000 (2.0 с), сформированные
только вокруг сегментов речи. Короткие сегменты описываются реальной длиной и должны быть
дополнены в model adapter вместе с маской длины. Если суммарной речи меньше 2.5 с,
конвейер завершает обработку статусом `insufficient_speech`, не выдавая вероятность.

На следующем ML-этапе модель будет возвращать logit каждого окна. Только после агрегации
logit-ов на уровне записи и отдельного temperature scaling допустимо показать `p_ai`.
